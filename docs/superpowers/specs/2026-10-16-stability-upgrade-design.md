## 目标与边界

第一版让现有规则更可靠、工具更容易复用、后续合作更容易验证。继续使用纯静态页面、Canvas 和仓库现有 Matter.js；无需引入前端框架、账号系统或服务端。

本次不调整投放概率、计分、判负线、碰撞体尺寸、角色素材或整体美术风格。这些数值变更应另行约定，避免在修复时改变难度。

## 组件与职责

### 游戏规则：`www/game.js`

- 修复同阶角色在出生冷却期内接触后，冷却结束却没有再次检查合成的问题。
- 接触开始时记录因冷却暂缓的候选角色对；到期时确认两只角色仍然存在、同阶、未被使用、不是顶级，并且真实碰撞几何仍接触，才允许合成。
- 检查不依赖休眠角色持续发出碰撞事件，避免角色休眠后永远失去合成机会。
- 已分离、已移除或已经参与其他合成的候选及时失效；重开清空候选和合成队列。
- 沿用现有批量合成流程，确保同一角色每轮只参与一次、计分一次。
- 将物理子步数的命名或注释与实际含义对齐；每帧模拟总时间不变，普通循环与调试推进保持一致。

数据流：碰撞检测 → 可立即合成或暂缓候选 → 冷却到期复核 → 既有合成队列 → 计分和特效。

### 回归检查：`tests/`、`package.json`

- 使用 Node 内置测试工具与仓库自带的 Matter.js，运行真实碰撞与合成逻辑。
- 页面相关接口使用最小环境替身；物理和游戏规则保持真实实现，不以替身代替被验证的规则。
- 提供 `npm test` 入口；基础规则测试无需安装素材抠图模型。
- 失败输出说明触发场景和实际状态，便于双方定位回归。

### 素材验收：`scripts/preview.js`

- 对齐当前构建输出的八阶素材名称，展示全部角色。
- 检查品红、深色、棋盘格三种背景的输出，确认背景生成调用可运行。
- 生成操作在明确的输出目录内进行；输入目录缺失或图片缺失时，给出具体路径并以非零状态退出。
- 支持直接使用仓库已提交的游戏图片检查预览，使首次验收不必重新运行 AI 抠图。

### 文档与持续检查：`README.md`、`.github/workflows/`

- 说明当前五阶投放权重、四个物理子步、实际碰撞体方案与素材处理命令。
- 区分直接运行游戏、运行规则测试、重新构建素材所需步骤。
- 为 PR 和分支推送配置轻量规则检查；基础检查不下载 AI 模型。
- CI 只验证，不部署、不自动合并。

## 错误与兼容处理

- 暂缓候选只引用当前局内角色；任何角色状态改变都先验证再操作，避免幽灵合成和重复加分。
- 继续容忍本地最高分存储不可用的场景，不让存储异常打断游戏。
- 素材工具失败要指出缺失输入，不能生成看似完整却少了角色的验收图。
- 普通运行仍可直接执行 `node serve.js 5173`；静态托管方式不变。

## 验收标准

1. 两只同阶角色在 500 ms 出生冷却内接触，持续接触到冷却结束后能合成一次并正确计分。
2. 同一场景中角色已经休眠，也能在冷却结束后合成。
3. 冷却期间分离的角色不会隔空合成。
4. 三只同阶角色同时接触时，同一角色不会被重复使用，分数与最终角色数一致。
5. 不同阶不会合成，顶级角色不会继续合成，普通投放合成仍然通过。
6. 重开后不保留上一局候选或待执行合成；最高分行为保持原有约定。
7. 使用已提交的游戏图片，可以生成包含八阶角色的三种背景验收图。
8. 本地规则测试与持续检查通过，文档参数与实现一致，改动清单无无关文件。
9. 如浏览器交互测试可用，补验拖放、重开及手机尺寸布局；如环境仍阻止交互，在 PR 中明确未验证项，不用逻辑测试替代真机体验结论。
